# 门店设备自动摆放求解器（居灵 Take-Home 工程题）

给定任意多边形轮廓、一到两扇门（各自可内开/外开）与若干矩形设备，自动求出一套
**不越界、不重叠、不挡门、物品沿墙单排排布、中央留出人行通道**的摆放方案，
输出每件物品的中心点坐标与旋转角度。

语言：**Python 3**（核心求解只用标准库，出图需要 Pillow）。

---

| example2（题目） | 8 | 1 | 0° | 0° / 90° | ✅ | 7/8 | inner | **64%** | 800 | 36 s |

耗时为本机（i5-1130G7）实测，**结果可复现**：搜索预算以节点数为准而不是墙钟时间，
同一份输入连跑两次给出的是逐件相同的解（见第五节）。

全部通过内置自检（在轮廓内 / 互不重叠 / 未挡门 / 未侵占中央通道 / 冰箱开门侧无遮挡）。
输出 JSON 在 `output/*.json`，示意图在 `output/*.png`。

> **空间利用率不作为优化目标。** 它由输入决定——物品多大、房间多大是给定的，算法
> 能优化的是"贴不贴墙、有没有挡路"。输出里仍然给出利用率，但标注为参考值，
> 不参与方案择优。

### 三个关键指标怎么读

* **贴墙件数 / 墙边利用率** —— 直接回答"墙边有没有被浪费"。题目要求"优先全部贴墙"，
  这是本项目首要优化目标。
* **层级** —— 实际用到的降级层级（见 1.2）：
  `wall` = 全部贴墙 / 沿墙左右紧邻；`inner` = 沿墙一排排不完，部分物品贴着第一排
  又放了一排；`free` = 连内核都放弃，剩下的摆到房间中央。
* **通道** —— 中央保证留出的人行宽度（默认 800）。房间实在挤不出就自动收窄
  （800 → 640 → 600），再不行就取消并在 `reason` 里写明。

example3 / example6 之所以"未保留通道"，是因为**复核**没过：贴墙摆完之后用另一套
代码路径（栅格腐蚀 + 连通域 + 门可达）重算，发现门走不进来。与其给一个看着漂亮、
实际堵门的方案，不如如实取消通道约束（详见 1.4）。

## 一、核心代码实现逻辑

### 1.1 摆放规则（本版的核心思路）

题目要求"优先考虑所有物品均贴墙放置"，但没有说贴不下的时候怎么办。我把它落成
一条**结构性**的规则，而不是一条打分偏好：

```
1. 每件物品贴墙，面宽（length）与墙面共线 —— 斜墙也一样，斜着贴。
2. 贴不下时只能沿墙面方向"左右紧邻"另一件物品，排成一排继续往两边延伸。
3. 不许垂直于墙面往房间里凸出去摆第二层。
4. 全部贴墙之后，房间中央自然剩下一整块空地 = 通道。
5. 沿墙排不完时按 wall → inner → free 逐级降级。
```

第 3 条是**靠候选生成方式强制成立的**，不是靠打分劝退：`solver._rect_faces` 规定
已放物品只有"与所贴墙面垂直的两条端面"能当新的贴面，朝内那一面在标准层里根本
不在可贴面列表里——结构上也就不可能凸出去。

**降级顺序为什么是"再贴一圈"优先于"摆到中央"**：贴在第一排朝内那一面的物品，
背后仍有支撑、正面仍朝通道，比起孤零零杵在房间中央，无论从门店实际还是从
"尽量贴墙"的题目要求看都更好。摆到中央是最后一步，代价是放弃通道保证。

### 1.2 题目约束 → 实现方式

| 题目要求 | 本项目的实现方式 | 可调参数（`layout_solver/config.py`） |
|---|---|---|
| 物品在轮廓内、互不重叠 | 矩形四角在多边形内（奇偶规则）+ 矩形边与轮廓边无"穿透式"相交；物品间用 SAT 分离轴判穿透 | `CONTACT_TOL` `OVERLAP_TOL` `INSIDE_TOL` |
| 可旋转，需与轮廓边平行或垂直 | 由轮廓边方向按 mod 90° 聚类出所有合法朝向族，**逐族求解后择优**；族内物品角度 = 族角度 或 +90° | `FRAME_CLUSTER_TOL` `FRAME_SNAP_TOL` |
| 优先考虑全部贴墙 | 候选只从"可贴的面"生成；贴墙层（level 0）只放行真正贴到墙的候选；方案择优键 = 贴墙件数 → 墙边利用率 → 贴墙面积占比 | `RING_LEVELS` `MAX_BRANCH` `NODE_BUDGET` `TIME_BUDGET` |
| 不许垂直墙面凸出第二层 | 已放物品只有沿墙切向的两条端面能当贴面（见 1.1） | 结构强制，无开关 |
| 不可遮挡门 | 门洞线段不允许被矩形压到；门洞正前方另留 `门宽 × DOOR_CLEARANCE_DEPTH` 的禁放区；门两侧墙面留 `DOOR_SIDE_CLEARANCE` 不贴设备 | `DOOR_CLEARANCE_DEPTH` `DOOR_SIDE_CLEARANCE` `DOOR_CLEAR_DEPTH` |
| 内开门占据 N×N | 每扇内开门在门内侧放一个 N×N 方形禁放区（随朝向一起旋转） | 自动，由每扇门的 `isOpenInward` 触发 |
| 留出人行通道 | 摆放时查"设备朝内那一面到最近障碍的净空"；出结果后再用栅格腐蚀 + 连通域 + 门可达独立复核一遍 | `ENABLE_AISLE` `AISLE_WIDTH` `AISLE_MIN_WIDTH` |
| 人的操作空间 | 设备贴墙后，交互面朝内，正前方净空须 ≥ 通道宽与操作深度取大者 | `ACCESS_DEPTH` `FRIDGE_ACCESS_DEPTH` `MIN_ACCESS_DEPTH` `FRIDGE_MIN_ACCESS_DEPTH` |
| 墙边要充分利用 | 打分里加"**新占用的墙长**"奖励：优先去占还没人用的墙段，而不是挤在已放物品旁边 | 打分第 2 项，见 1.3 |
| 冰箱 length 边为开门边，不能放东西 | 开门边 = 所贴墙面的**对面**（后背贴墙、门朝室内），且必须是 length 边；后续任何物品不得压入这条 1 mm 探测带 | `FRIDGE_OPEN_BUFFER` `FRIDGE_DOOR_CLEAR` |
| 货架的边可以放东西 | 物品之间允许"紧贴"（穿透 ≤ 1 mm 视为接触而非重叠） | `OVERLAP_TOL` |

**工程假设（题目没写死、我按字面 + 可落地的方式定的，全部可改）：**

1. **`length` 是面宽、`width` 是进深**。题目说"冰箱 length 的其中一边为开门边"，
   说明开门面宽度 = `length`；货架 1000×400（1000 面宽、400 进深）、制冰机
   760×850、冰箱 1220×1330 全都符合这个约定。于是"贴墙"就明确了：**面宽沿墙、
   进深朝内**（`solver._orientation_ok` 强制）。把进深沿墙摆等于让设备往房间里
   戳出一根刺，既破坏环形也啃掉通道。
2. 门洞禁放按"不可遮挡"执行：门洞线段不许压，门洞正前方另留一块通行缓冲。
   这块缓冲**只禁放设备，人是可以走的**（判通行时不算障碍）——否则等于要求门口
   永远不能站人，房间会瞬间变紧。
3. 离地架（overShelf）按平面占地处理，**不与其他物品投影重叠**。现实中它架空在
   地面之上，若允许投影重叠可再放宽，但会让"互不重叠"这条硬约束的解释变复杂，
   这里取稳妥口径。
4. 同一个方案里所有物品共用一个朝向族（平行或垂直于同一组墙），与门店实际摆放一致。

### 1.3 算法流程

```
预检：物品占地 > 房间面积 - 禁放区 ？→ 直接判定不可行（秒回，不用搜索）
for 通道档位 800 → 640 → 600 → 0:                    # 逐级收窄，最后才取消
    for 每个合法朝向族 θ（由轮廓边方向 mod 90° 聚类得到，通常 1~2 个）:
        把整个房间（轮廓 / 门 / 禁放区）旋转 -θ
            → 该朝向下所有物品都是轴对齐矩形，"贴墙"退化成"把矩形推到某条线上再滑"
        for level in (wall, inner, free):             # 逐级降级，放不下的交给下一级
            for 每种摆放顺序（面积降 / 最长边降 / 面积升）:
                DFS：每件物品 → 枚举候选 → 校验 → 打分排序 → 按分尝试 → 失败回溯
            这一层放得下的先摆好，剩下的交给下一层
    该档位能全放下 且 通道复核通过 → 定为最终档位，精修一遍
最后：算指标，并独立自检一遍
```

**候选位置怎么来的**（`solver.gen_positions`）：对每个"可贴的面"（真实墙 + 已放物品
的合法端面 + 禁放区边），把矩形贴上去再沿面滑动。滑动的候选点取：

* 面的两个端点（贴角）；
* 所有轮廓顶点、已放物品边界、禁放区边界的投影（对齐已有物体，不产生错位缝隙）；
* 等距采样点（`SLIDE_STEP`，默认 150 mm，兜底）；
* 摆到中央那一级（`free`）额外做一次网格扫描——大件在只剩中央空地时，光靠"贴面"
  生成会无处可去。

**打分**（越小越优先）：

```
贴墙级别：贴角(0) > 贴一面墙(1) > 只贴物品/贴禁区(2~3) > 悬空(5)
   ↓ 同级别内依次比较
新占用的墙长（越长越好）  ← 让墙边被充分利用，而不是挤在已放物品旁边
   ↓
接触长度（贴得紧） → 离已放物品群的距离（权重最低，只用来打破平局）
```

**DFS 为什么允许"跳过"**：贴墙层不追求一次放完——能贴几件贴几件，剩下的交给下一
级降级处理，而不是因为最后一件塞不进去就把整层判失败。每个节点都先试"放下去"
（在若干个候选里挑，剩下的能全放上就收工，否则换候选看谁最终放得多），再试
"跳过"，两边按 `(件数, 贴墙件数, 贴墙总长)` 取优。

> 这里踩过一个坑：上一版写的是 `if len(res) >= len(placed): return res`，而 `res` 是
> `placed` 的超集，条件恒真——于是第一个能放的候选直接定死、再也不回溯，DFS 退化成
> 纯贪心，表现为"冰箱占了地方导致后面的货架放不下也不回头换"。唯一的提前返回条件
> 必须是"剩下的物品全放上了"。

**为什么这么做**：这类布局问题本质是带旋转的 2D 装箱（NP-hard），精确解代价太高。
用"贴面滑动 + 打分 + 有限回溯"，能在秒级给出**可解释、可复现、贴墙率高**的方案。
搜索受节点数与时间预算双重限制；换候选的次数还按深度递减（浅层的大件值得多试几个
位置，深层填满缝的小件基本一次成功），否则搜索树会几何级膨胀。

### 1.4 通道：摆放时用局部判据，出结果后用全局复核

两套完全不同的代码路径，两边都过才算真的留出了通道。

**摆放时（局部、便宜）** `solver.front_clear_ok`：设备贴墙 → 交互面朝内 → 从交互面
沿法向发射线，量到最近障碍（墙 / 另一件设备 / **内开门门扇**）的距离，要求不小于
`max(通道宽, 该设备的操作深度)`。

* 沿交互面取 5 个采样点（两端、两个四分点、中点）并取**中位数**，不是最小值。
  设备一端顶着侧墙或柱子时那个点净空必然是 0，取最小值会把本来站得下人的位置
  误判成不行；中位数衡量的是"设备正前方大部分区域"的空档。
* **门洞前的通行缓冲、门侧净空条不算障碍**——它们是给人走的，人不站在那里才奇怪。
  内开门门扇算障碍（门板挡着，人确实站不进去）。

**复核时（全局、独立）** `solver.corridor_report`：把自由空间打成栅格 → chamfer 距离
变换 → 腐蚀 `通道宽/2` → 连通域分析 → 检查每扇门是否还走得到。这是摆放阶段完全没
用过的另一条路径。探测通道档位时也会跑它：**某一档能摆下全部物品、但复核发现门
走不进来，就判这一档的通道是假的，继续收窄**。

example3、example6 就是这样被判成"未保留通道"的——不是摆不下，是摆完之后门进不来。

> 上一版用"到最近墙面的距离场"定义中央内核（`内核 = {p : dist(p, 墙面) >= CORE}`），
> 有两处不好用：① 那是**对称**判据，房间窄、只有一侧贴大件时会被误杀；
> ② 拿它判断"某条边是不是朝向房间内部"完全失效——贴着一面长墙摆的时候整条带子
> 都被那面墙支配，沿墙方向走多远距离数值都不变。现在距离场只用来画通道和估面积。

### 1.5 关键几何判定（`layout_solver/geometry.py`）

* **点在多边形内**：奇偶规则 + 边界容差。用奇偶规则而不是环绕数，是因为题目数据里
  存在自接触/重复边（example4 左墙被重复描了两遍），奇偶规则对这种退化输入仍然稳定。
* **矩形在多边形内**：四角在轮廓内（容差 1 mm，允许贴边）+ 矩形边与轮廓边无"穿透式"
  相交。共线重叠不算相交 —— 否则贴墙摆放会被误判成越界。
* **矩形重叠**：SAT 分离轴定理，取 4 个轴的最小穿透深度，> 1 mm 才算重叠（紧贴合法）。
* **是否挡门**：线段与矩形闭合区域的 Liang–Barsky 裁剪，含端点接触与共线重叠。
* **冰箱开门侧**：开门边外侧生成 1 mm 探测带，要求探测带完全在轮廓内（门朝室内打得开），
  之后任何物品不得压入（薄带判重叠时用 0.01 mm 容差，避免被 1 mm 容差吃掉）。

### 1.6 收尾修正与自检

* **收尾修正** `solver.repair_overlaps`：摆放是在旋转坐标系里做的，斜朝向时"贴墙"会有
  零点几毫米的浮点误差，两个分别贴不同墙的物品可能互相压进一点点。最后在世界坐标下
  用最小平移向量把它们推开（亚毫米级），推完再复核一遍。交付的结果是**零重叠**的。
* **自检** `layout_solver/verify.py`：在世界坐标下用另一套代码路径重新检查一遍
  （求解是在旋转坐标系里做的），避免"自己判自己"：物品是否都在轮廓内、两两是否重叠、
  是否压门洞/内开门区、通道复核是否通过、冰箱开门侧是否被挡。跑 `main.py` 时自动执行。

## 二、运行环境与运行方式

* Python **3.8+**（实测 3.13 可跑）
* 核心求解：**零第三方依赖**（只用标准库）
* 出 PNG 示意图需要 Pillow：`pip install pillow`（不装也不影响求解，会自动跳过出图）

```bash
git clone <你的仓库地址>
cd layout-solver
pip install -r requirements.txt        # 可选，只为出图

python main.py                          # 跑 examples/ 下全部样例

```

输入格式（两种都支持，旧格式向后兼容）：

```jsonc
{
  "boundary": [[x, y], ...],
  // 推荐：门可以是一扇或两扇，各自标注内/外开与角色
  "doors": [
    {"points": [[x1, y1], [x2, y2]], "isOpenInward": true,  "role": "enter"},
    {"points": [[x1, y1], [x2, y2]], "isOpenInward": false, "role": "exit"}
  ],
  // 兼容写法：单扇门
  // "door": [[x1, y1], [x2, y2]], "isOpenInward": false,
  "algoToPlace": {"fridge": [1220, 1330], "shelf-1": [1000, 400]}
}
```

单文件调用：

```python
from layout_solver.scene import load_scene
from layout_solver.solver import solve, solution_to_dict, compute_metrics
from layout_solver.verify import verify

scene = load_scene("examples/example6.json")
sol = solve(scene)
print(solution_to_dict(scene, sol))     # 结果字典（含 metrics）
print(compute_metrics(scene, sol))      # 只看空间指标
print(verify(scene, sol))               # [] 表示自检通过
```

输出字段：

```jsonc
{
  "feasible": true,                 // 是否可行
  "frame_angle": 20.0,              // 该方案采用的朝向（度）
  "ring_level": "inner",            // 实际用到的降级层级 wall / inner / free
  "wall_hugging": "3/9",            // 贴墙件数
  "wall_usage": 0.32,               // 墙边利用率
  "aisle_width": 800.0,             // 实际保证的通道宽（0 = 没留通道）
  "reason": "",                     // 收窄/取消通道或不可行的说明
  "metrics": {
    "room_area": 10080000,          // 房间轮廓面积
    "items_area": 4588600,          // 物品占地
    "utilization": 0.455,           // 利用率（参考值，不参与择优）
    "usable_wall_length": 13200,    // 该朝向下可贴墙的总长度
    "core_area": 2082381,           // 中央内核面积
    "facing_core": 7                // 交互面朝向中央的物品数
  },
  "placements": [
    {
      "name": "fridge",
      "type": "fridge",
      "center": [51999.88, 52632.78],  // 中心点坐标
      "angle": 110.0,                  // 相对给定 (length, width) 初始姿态逆时针旋转的度数
      "size": [1220.0, 1330.0],
      "wall_contacts": 2,
      "ring_level": 0,                 // 0=贴墙 1=再贴一圈 2=中央
      "fridge_opening_side": "left"    // 仅冰箱：开门边朝向
    }
  ]
}
```

角度约定：`angle = 0` 表示 length 沿 +x、width 沿 +y；`angle = 90` 表示整体逆时针转 90°
（length 沿 +y）。朝向族非 0 时输出的就是族角度或其 +90°，例如 example6 的 20° / 110°。

## 五、已知边界与可继续优化的点

* **非凸 / 退化轮廓**：已能处理凹口、狭长房、重复边（example4 左墙被描了两遍）、
  斜墙与旋转房间；但对真正自相交（"8 字型"）的多边形不做处理。
* **贴墙率受房间形状限制**：example1 / example5 的可贴墙长（5,754）小于所有物品面宽
  之和（6,780），客观上贴不下，只能部分降级到 `inner`。这是房间的问题不是算法的问题。
* **搜索是启发式的**：不保证在所有输入上都找到解（NP-hard 问题的固有代价）。
  放不下时返回 `feasible=false` 并给出原因与未放下清单。想加强搜索就把
  `NODE_BUDGET` 调大（这是主约束），或把 `SLIDE_STEP` 调小（更精细但更慢）。
  `TIME_BUDGET` 只是病态输入下的兜底闸，调小它会让结果依赖机器负载、不可复现。
* **结果可复现**：搜索预算以**节点数**为准，不用墙钟时间当主约束。
  同一份输入连跑两次给出的是逐件相同的解（实测 7 个样例的贴墙数、层级、
  墙边利用率与每件中心点全部一致，只有耗时不同）。
* **单样例耗时 3~40 秒**（本机 i5-1130G7）：主要花在回溯搜索上。已做三处优化——
  候选集按"已放了什么"缓存（回溯会反复回到同一局面）、换候选次数按深度递减、
  `frame.edges` 缓存轮廓边表（每个候选都要算一次贴墙长度，这是最热的一行）。
* **只做平面摆放**：不考虑高度方向，离地架默认按占地处理（见 1.2 假设 3）。
* **可以加的改进**：① 同类物品集中摆放、离门远近等多目标打分；
  ② 用"最大空矩形"做初始布局再局部搜索；③ 把解导出成 DXF/CAD 可直接用的格式。
